# cssmt — Plan d'implémentation (phases 0, 1 et 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** transformer un clone de tf2mt en `cssmt.app`, qui installe et lance Counter-Strike: Source (Windows, appid 240) sous Wine en DXVK sur le Mac du propriétaire, avec le lanceur complet, puis mesurer les performances M1 pour décider du rendu Metal.

**Architecture :** fork git de tf2mt (remote `upstream`). Toute constante propre au jeu est centralisée dans `scripts/_env.sh`. Les scripts bash pilotent Wine/Steam/le jeu. Le lanceur SwiftUI appelle ces scripts. Deux nouveautés : `scripts/presets.sh` (remplace mastercomfig) et `tools/display/display120` (bascule l'écran à 120 Hz). Les phases 2 et 4 (rendu Metal pour CS:S, fluidité 120 Hz sur Metal) feront l'objet d'un **plan séparé**, après le point de décision de la tâche 8.

**Tech Stack :** bash 3.2 (macOS), Swift/SwiftUI via `swiftc` (Command Line Tools, sans Xcode), CoreGraphics, Wine 10 x86_64 sous Rosetta (runtime tf2mt), DXVK, mingw-w64, Python 3 (outils de bench).

**Spec :** `docs/superpowers/specs/2026-10-28-cssmt-design.md`

## Global Constraints

- Jeu : Counter-Strike: Source Windows, **appid 240**, dossier `Counter-Strike Source`, `-game cstrike`.
- Racine des données : `CSS_HOME="${CSS_HOME:-$HOME/Games/css}"`.
- **Ne jamais modifier les binaires du jeu ni injecter quoi que ce soit dans son processus**, à part `d3d9.dll` (DXVK, proxy de trace ou couche tf2mt). Les tests automatisés ne rejoignent **jamais** un serveur en ligne. Les tests en ligne sont faits par le propriétaire.
- Rendu par défaut : **DXVK**. Le rendu Metal reste une option, désactivée par défaut.
- Cible : **120 fps à 120 Hz, 2560×1440**. Machine : MacBook Pro M1 (8 cœurs GPU), 16 Go, macOS 27, capot fermé, seul écran = G27UP (natif 160 Hz).
- **Pas d'auto-update** : pas de bouton Update, pas de vérification de releases GitHub.
- Ne renommer que ce que voit l'utilisateur. Garder les noms internes du rendu (`tf2mt.dll`, `tf2mt.so`, variables `TF2MT_*`, `src/**`) pour faciliter les merges avec upstream.
- Ne jamais écraser `config.cfg` ni un `autoexec.cfg` du joueur.
- Ne jamais plafonner `fps_max` à 120 (leçon tf2mt : laisser vsync/DXVK cadencer).
- Licence MIT de tf2mt et `THIRD_PARTY.md` conservés.
- Pas de commit/push vers GitHub sans demande du propriétaire (commits locaux OK).

## Review Focus

1. **Session qui se termine mal** (crash du jeu, Mac mis en veille, lanceur tué de force) : l'écran doit revenir à son mode d'avant au plus tard au lancement suivant. → Tâche 6, test `test_stale_restore`.
2. **Le joueur a déjà son `autoexec.cfg`** : le préréglage ajoute une seule ligne marquée, `none` retire uniquement cette ligne, le reste du fichier reste identique à l'octet près. → Tâche 5, tests `test_preset_keeps_user_autoexec` et `test_none_restores_exactly`.
3. **Chemins avec espaces** (`Counter-Strike Source`, `Program Files (x86)`) : chaque script doit marcher avec un `CSS_HOME` qui contient aussi un espace. → Tâche 2, `test_env_paths_with_spaces`.
4. **Écran sans mode 120 Hz** (autre écran, câble limité) : on ne touche à rien et on l'écrit dans le log. → Tâche 6, `test_pick_mode_none_when_missing`.
5. **Résidus TF2** dans un chemin rarement exécuté (sweep, stop, run-exe) : un `pgrep` qui vise encore `tf_win64` laisserait Wine tourner. → Tâche 4, `test_no_tf2_refs`.

### Task 6 : Bascule de l'écran à 120 Hz

**Files :**
- Create : `tools/display/DisplayModes.swift` (logique pure), `tools/display/display120.swift` (CLI CoreGraphics), `tests/unit/display_modes_tests.swift`
- Modify : `Makefile` (cibles `display120` → `build/tools/display120` et `test-display`), `scripts/play.sh`, `scripts/session-end.sh`, `tests/scripts/test_display_hooks.sh`

**Interfaces :**
- `struct ModeInfo: Equatable { let id: Int32; let width: Int; let height: Int; let pixelWidth: Int; let pixelHeight: Int; let hz: Double }`
- `func pickMode(_ modes: [ModeInfo], current: ModeInfo, hz: Double) -> ModeInfo?` : même `width`/`height`/`pixelWidth`/`pixelHeight` que `current`, `abs(m.hz - hz) < 0.5` ; renvoie `nil` sinon.
- CLI : `display120 set <statefile>` écrit l'`id` du mode courant dans `<statefile>` puis bascule l'écran principal (`CGMainDisplayID()`) avec `CGConfigureDisplayWithDisplayMode` et `.forSession`. Ne fait rien si le mode courant est déjà à 120 Hz. Si `pickMode` renvoie `nil` : affiche `no 120 Hz mode for <w>x<h>, unchanged`, sort avec 0, sans écrire le fichier. Si plusieurs écrans sont actifs : avertissement `several displays active, switching main only` sur stderr. `display120 restore <statefile>` remet le mode d'`id` enregistré, puis supprime le fichier. Sans fichier : sort avec 0 sans rien faire.
- Hooks : `play.sh` appelle d'abord `display120 restore` (reste éventuel d'une session précédente), puis `set "$CSS_HOME/run/display-before"` si `CSS_DISPLAY_120=1` (défaut 1). `session-end.sh` appelle `restore`. Le binaire est cherché dans `$CSSMT_ROOT/build/tools/display120` ; s'il est absent, on ne fait rien.
